# x-advanced-http

Server 02 in the series: the X (Twitter) server from
[`mcp/01-x-basic-stdio`](https://github.com/ht0rohit/mcp-server/tree/mcp/01-x-basic-stdio), taken end to end. It runs over
**Streamable HTTP** behind bearer-token auth, returns **typed results**, reports **progress**,
**asks the user before it posts or deletes**, tells subscribers when their data changed, and
**completes** arguments as you type. It is built on the official Python SDK v2 (`MCPServer`) and
speaks the 2026-07-28 protocol, while still serving older (2025-11-25) clients.

## What it exposes

**Tools.** Every tool returns a Pydantic model, so each one publishes an `outputSchema`.

| Tool | X endpoint | Notes |
|---|---|---|
| `x_get_user` | `GET /2/users/by/username/:username` | Cached for 5 minutes |
| `x_get_users` | `GET /2/users/by` | Up to 100 handles; lists the ones not found |
| `x_get_post` | `GET /2/tweets/:id` | Includes the post URL |
| `x_get_posts` | `GET /2/tweets` | Up to 100 IDs; lists the ones not found |
| `x_get_user_posts` | `GET /2/users/:id/tweets` | Replies and reposts excluded unless asked; `next_cursor` |
| `x_get_user_mentions` | `GET /2/users/:id/mentions` | `next_cursor` |
| `x_search_recent_posts` | `GET /2/tweets/search/recent` | Last 7 days; `next_cursor` |
| `x_search_digest` | `GET /2/tweets/search/recent`, paged | Up to 500 posts, **progress** per page; top posts, authors, languages |
| `x_create_post` | `POST /2/tweets` | Needs `x:write` and a user token; **asks the user to confirm**; X enforces the length (weighted characters) |
| `x_delete_post` | `DELETE /2/tweets/:id` | Needs `x:write` and a user token; **asks the user to confirm**; destructive |

The two write tools only appear when `X_USER_ACCESS_TOKEN` is set.

**Resources**

| URI | What |
|---|---|
| `x://guides/search-operators` | Markdown cheat sheet for search queries |
| `x://users/{username}` | Template: a user's profile as JSON; `username` autocompletes |
| `x://me/posts` | The signed-in account's latest posts. Subscribers are notified after each write. Needs a user token |

**Prompts**: `profile_brief(username)` and `topic_pulse(topic, language)`. Both `username` and
`language` autocomplete.

**HTTP routes**

| Route | Auth | What |
|---|---|---|
| `POST /mcp` (and `GET`/`DELETE` for older clients) | Bearer token with `x:read` | The MCP endpoint |
| `GET /.well-known/oauth-protected-resource/mcp` | None | RFC 9728 metadata, generated by the SDK. It names this server as the authorization server as a placeholder: nothing here issues tokens, so clients must send the static `Authorization` header |
| `GET /healthz` | None | `{"status": "ok"}` for load balancers |

## How the code is organized

`OVERVIEW.md` walks through the code with flow diagrams.

```
src/x_advanced_http/
├── server.py   # the MCP part: tools, resources, prompts, completions, middleware,
│               # create_server(config), create_app(config), main()
├── config.py   # every setting, read from the environment and validated at startup
├── auth.py     # StaticTokenVerifier and the per-tool scope check
├── client.py   # async X client (reads, writes, retries) and the user cache; no MCP here
├── models.py   # the Pydantic models tools return
└── __main__.py
tests/
├── conftest.py      # fake X API (httpx.MockTransport), clients in-process and over HTTP
├── test_server.py   # every feature through the protocol, in-process
├── test_http.py     # routes, 401s, scopes and the Host allowlist, against the real ASGI app
├── test_process.py  # starts the real server on a port and connects over HTTP
└── test_config.py   # bad settings fail fast with a clear message
```

Start with `server.py`: its docstring lists what is new since server 01, and the file reads top
to bottom.

## Run it

You need an X API app-only **bearer token** for the read tools. For the write tools you also need
an OAuth 2.0 **user access token** with `tweet.read`, `tweet.write` and `users.read`. X's free
tier blocks most read endpoints, so expect `403` errors unless your plan includes them.

Every client of this server needs a token too. Make one per client and give each the scopes it
should have:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

```bash
# from the repo root
uv sync --all-packages
export X_BEARER_TOKEN=...
export X_USER_ACCESS_TOKEN=...                            # optional: enables the write tools
export MCP_AUTH_TOKENS="<reader-token>=x:read;<writer-token>=x:read,x:write"
uv run --package x-advanced-http x-advanced-http          # http://127.0.0.1:8000/mcp
```

`.env.example` lists every setting. The server refuses to start without `MCP_AUTH_TOKENS`.

Try it in the MCP Inspector: start the server, run `npx @modelcontextprotocol/inspector`, choose
"Streamable HTTP", enter `http://127.0.0.1:8000/mcp`, and add the header
`Authorization: Bearer <writer-token>`.

### Claude Code

```bash
claude mcp add --transport http x-advanced http://127.0.0.1:8000/mcp \
  --header "Authorization: Bearer <writer-token>"
```

### Deploying it

- Put it behind TLS and set `MCP_PUBLIC_URL` to the URL clients use (`https://mcp.example.com/mcp`).
  Tokens are checked against it.
- Add that hostname to `MCP_ALLOWED_HOSTS` (`mcp.example.com,mcp.example.com:*`). Without it
  every request gets `421 Invalid Host header`: that is the DNS-rebinding protection working.
- More than one worker or replica: set the same `MCP_STATE_KEYS` on all of them, otherwise a
  confirmation answered on one worker can't be finished by another. Run with
  `uvicorn --factory x_advanced_http.server:create_app --workers 4`.
- Subscriptions to `x://me/posts` stay in one process. Across replicas you would give the server a
  shared `SubscriptionBus` (Redis pub/sub, for example).

## Test it

```bash
uv run pytest servers/x-advanced-http
```

No token or network is needed: X is replaced by a fake that answers like the real API (including
`200` with an `errors` array for missing items, `429`, and `503` to exercise retries), and the
HTTP tests run the real ASGI app in-process.

## What this server teaches

- **Streamable HTTP** with `streamable_http_app()`, a health route with `custom_route`, and a
  Host allowlist with `TransportSecuritySettings`.
- **Auth as a resource server**: a `TokenVerifier`, `AuthSettings` with `required_scopes`, the
  SDK's 401 and metadata document, and per-tool scopes with `get_access_token()`.
- **An app factory** (`create_server(config)`) so tests and production differ only in config,
  and **config that fails fast**.
- **Structured output** from Pydantic return types.
- **Progress** with `ctx.report_progress()` from a tool that pages through results.
- **Confirmation before side effects** with `Resolve(...)` and `Elicit(...)`: invisible to the
  model, one code path for new and old clients, and ordered so the scope check comes first.
- **Only expose what works**: the write tools and `x://me/posts` exist only with a user token.
- **Change notifications**: `ctx.notify_resource_updated()` after each write.
- **Completions** for prompt arguments and resource-template parameters.
- **Middleware** that logs every message with its caller and duration, never the token.
- **Retries that are safe**: only for GET and DELETE, bounded, with backoff.
